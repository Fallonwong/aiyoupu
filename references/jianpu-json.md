# JianpuJSON v1

JianpuJSON records written numbered notation for the image-to-video workflow. The frozen document is the source for layout, score proofreading and playback compilation. This stage delivers the data contract and validator.

## Structure

- `schema` is `aiyoupu-jianpu/v1`. `title` and optional `credits` preserve the source heading. `tonic` records displayed `1=X` as letter and accidental. Optional `tonic.octave` is the scientific-pitch octave of undotted 1 (C4 is middle C). Supply a reviewed octave for playback. `meter` records the displayed time signature.
- Fractions use `{"n":1,"d":3}`; a quarter note is one unit regardless of meter. Beat positions are zero-based and already include the effect of preceding tuplets. `measures` lists written order and system breaks; each measure explicitly lists active voices. A voice that has not entered is absent from the measure. A written rest in an active voice is a note record with degree 0. Optional measure `meter` changes the meter for that measure; repeat it on subsequent measures where it differs from the header. Optional `span` records a reviewed shorter bar such as a pickup. `barline` records the right boundary.
- `voices` names one upper row and optionally one lower row. Missing `hand` defaults to right for upper and left for lower. Each digit has its own `notes[].id`. Same voice, measure and beat means a vertical chord. Each voice fills each active measure by occupied time; simultaneous chord digits count once, using the longest duration. Later independent overlaps require separate voices.
- `degree` is 0–7. `octave` is the number of octave dots relative to undotted 1, negative below and positive above. `accidental` is the effective signed alteration relative to the degree; `accidentalSign` is written only where a glyph is present, including a visible natural. `fingering` stores an explicit or reviewed 1–5 marking.
- `duration` is the written value before tuplet scaling. It equals the quarter-note base divided by 2 per `durationLines`, dotted by adding halves of that base, plus one quarter per `extensionDashes`. For instance, a dotted eighth is 3/8 and a quarter with two extension dashes is 3. Optional `beamGroupIds` lists group IDs per underline level, outer list in order from the line nearest the digit downward. Use null for an unjoined line and reuse the same ID on digits joined at that level.
- `tuplets` stores ID, the number of written onsets, the ratio as normal count / written count, start and end anchors, above/below placement, and bracket style. Optional `label` preserves a displayed value such as 5:4. Three eighths in the time of two have count 3, ratio 2/3 and written duration 1/2 per note, giving 1/3 per note after one multiplication. Chord digits share an onset. A grouped rest occupies an onset.
- An anchor is either `{"noteId":"n12","edge":"start"}` (edge is start or end) or `{"measure":3,"beat":{"n":1,"d":2},"voice":"melody"}` (voice is optional for score-wide marks). `annotations` stores dynamic text, crescendos and diminuendos, accents, staccato, ties, slurs, tempo text/marks, and expression text. Hairpins, ties and slurs require two anchors. Ties link consecutive same-pitch segments. Slurs cover separate pitch events. Source glyphs and text are preserved; the playback adapter will map dynamics and articulations to performance values.
- `lyric.text` belongs to the note carrying it. `continuesOn` lists later pitched note IDs that share the syllable; optional `punctuation` preserves adjacent written punctuation without assigning another onset.
- `tempo` is a numeric quarter-note BPM table. Entries start at score beat zero; `transition` governs the segment to the next point (`step` holds the BPM, `linear` varies BPM linearly in score beats). `annotationId` links a playback choice to the visible source marking. Keep words such as 中速 and 渐慢 in annotations. If numeric tempo is unknown, leave the table empty until reviewed rather than guessing.
- Optional `source` boxes locate notes and marks; each unresolved `issues` entry requires a box. Boxes use one-based page numbers and original-image pixel coordinates `x`, `y`, `width`, `height`, and may also name a line and measure. Images, recognized private transcriptions and approvals live in the song workspace.

## Verification and stops

```powershell
node --test scripts/jianpu-check.test.mjs
node scripts/jianpu-check.mjs <path-to-score.jianpu.json>
```

The validator reports `invalid` and exits 1 on missing required fields, bad geometry anchors, gaps, overlaps, invalid tuplets or other structural errors. A structurally valid draft with unresolved image observations has status `needs_source_review`. `readyForPlayback` additionally requires a resolved initial tempo, octave register and playback mapping for recognized gradual tempo text; it never grants human approval. Exit 0 means the structure is valid. A downstream command must also check readiness and the actual approval record.

Stop immediately for an unreadable tonic or time signature. Show all other unresolved image readings with their original-image boxes and wait before freezing. Ask for performance choices when a video needs unspecified tempo, gradual tempo change or register. Phase 2 will exercise audio and video against reviewed examples. Phase 3 will submit actual image crops and proofing renders for human approval.

## Phase 2 operator path

1. Run `aiyoupu jianpu proof --source SCORE --out PROOF` and `aiyoupu jianpu review --proof PROOF --out REVIEW`. An optional `--reference CROP.png` includes the exact reference image in the approval bundle. Show the proof and obtain the user's score and audio choice via the existing `approve` command.
2. For sampled piano, run `aiyoupu jianpu audio --proof PROOF --score-approval APPROVAL --musescore EXE --soundfont FONT --out AUDIO`. The temporary MusicXML is an audio-engine input. The score SVG always comes from JianpuJSON. The adapter probes MuseScore's MIDI output and requires matching note attacks, velocities and onsets before WAV export through the existing sampled renderer and master.
3. Run `aiyoupu jianpu prepare --proof PROOF --score-approval APPROVAL --browser EXE --out PREPARED --audio WAV --audio-evidence RECEIPT`. Existing user recordings also need `--map` with a reviewed time map. The prepared folder contains the aligned timeline, measured layout evidence and a direction preview. Choose and derive a direction through the existing CLI, then use `bind --source-type jianpu-json --score-review PROOF/check.json` with the existing production, layout, audio, quality and score-approval arguments. Layout evidence must match the final timeline if the direction changed the camera path. Use existing keyframes, audition, approval and render commands.
4. Before publishing, verify the first four measures and risky points across the complete arrangement. Record source/audio review for formal quality. A sampled MIDI probe verifies the engine's event output. Review the actual video and waveform for visible and audible sync.

Ties and slurs retain written identities and are compiled by the existing music-motion module. The audio adapter uses the same generated note IDs and scores its audit against the expected pitches, velocities and times. Any stale proof or audio bundle, unresolved performance tempo, changed file or failed onset audit requires review before export.

## Phase 3 image path

1. Use a vision-capable Agent to measure the original raster image. Create a `aiyoupu-jianpu-regions/v1` plan with `heading`, `lines[].box`, and each measure's written number, box and upper/lower row boxes. Boxes use original pixels. Use `deskewDegrees` for a measured correction (zero for a straight page) and `scale` for magnification.
2. Run `aiyoupu jianpu image-crops --image IMAGE --regions PLAN --out CAPTURE`. Read each measure following `recognition-request.json` and its exact crops. The Agent's vision is the recognition stage. Return the JianpuJSON draft with one original-image source box per note, annotation and uncertainty. Read adjacent line context for cross-bar marks and a late-entering voice. Keep interpretation choices tied to the user's actual direction.
3. Run `aiyoupu jianpu image-audit --capture CAPTURE/capture.json --draft DRAFT --out AUDIT`. Missing key or meter returns `WAITING_FOR_HEADING`; show the heading crop and ask the user. Structural failures return `IMAGE_STRUCTURE_BLOCKED`. Source ambiguities and unresolved playback choices allow comparison for correction but block the approval route.
4. Open `AUDIT/comparison.html` and show original and proof together. Run `aiyoupu jianpu proof --source AUDIT/score.jianpu.json --image-audit AUDIT/image-audit.json --out PROOF`, then `aiyoupu jianpu review --proof PROOF --out REVIEW`. This fingerprints the original image, crops manifest, recognized score and exact displayed comparison. Obtain a real score approval before continuing with the same Phase 2 playback flow. Use `bind --source-type jianpu-image` and keep the image audit in the quality packet and its frozen evidence.

The deterministic audit verifies source coverage, anchor integrity and per-voice timing. Whole-score human review confirms the musical reading against the source. Each incoming image has its own capture, review and approval.
