## Direction workflow: Agent is the full path; the workbench is optional

The Agent must be able to complete the whole production path in the CLI without opening a browser: prepare MusicXML/MIDI, create a versioned direction preview, validate/export a direction, render a real still, save the direction, and derive the job/props for the existing keyframe review. `aiyoupu direction` is that path. `aiyoupu direction prepare --musicxml <score.musicxml> --audio <same-arrangement.mp3> --title <title> --out <preview-dir>` engraves with the installed Verovio/browser tools and measures the noteheads; `--midi` first uses the installed MuseScore 4 CLI. PDF/images require Agent notation recognition and a corrected MusicXML before this command; neither path invents notes. Use `direction validate`, `direction save`, `direction derive`, and `direction still` to produce an actual PNG without the browser UI. A generated score, direction, still or preview is not a human approval.

The direction console is the optional visual chooser for one already-prepared preview:

```sh
node <skill>/scripts/aiyoupu.mjs workbench open --preview <preview-dir>/preview.json --port 7801
```

Its first screen is the real Remotion canvas, transport, presets, common parameters, collapsed advanced parameters, and save-and-copy. It does not upload materials, prepare scores, list tasks, review notation, create keyframes, or record approvals. It reads only the named preview folder. Changing parameters keeps the current frame and audio state. Missing score/audio or a stale preview is reported explicitly; optional audio never triggers re-engraving. The saved short prompt contains only the direction ID and direction-file path. Both the Agent and this console call the same preset extraction, direction normalization, props derivation, and hash functions.

When a valid direction preview is ready, proactively tell the user: **「想更直观地看效果，可以对我说『打开工作台』，边播放边看运镜、光点和换行，也可以切换风格。」** If requested, open that preview and give the user its link. A direction preview does not replace either content approval.

After a direction is saved, run `direction derive --direction <saved-direction.json> --project <existing Remotion project> --out <job-dir>`. This creates a visual-direction draft and keeps its assets under the job's `public` tree. Continue formal production through `aiyoupu bind` with `--asset-project <job-dir>`, the frozen props/production, real score review and v2 quality evidence; then use the existing `keyframes` command. The derived job explicitly marks a new keyframe review as required. Never reuse a previous keyframe approval. Do not treat `direction_draft` as a formal bound job.

The Agent conversation is the default human content gate: show the actual review material and quote the user's real response. An optional local page may be opened separately with `aiyoupu workbench review --request <review/request.json>` on another port only when every required item can be displayed; the score stage also records the audio choice. It is not part of the direction console, and its click credential still binds the actual displayed content. If the page cannot show all required content, use the Agent conversation instead.

## Before new video production

Use [production configuration and visual contracts](references/production.md). Run `aiyoupu focus-continuity --timeline FILE --strict` on the actual render timeline. It flags stepped movement, fast sweeps, and repeated braking. Rebuild a failing path with `camera-path` from measured geometry without retiming the notes or audio. Play a rendered clip across any row change before asking for keyframe approval. Compute camera and note motion per frame from `useCurrentFrame()`; CSS `transition`/`animation` never advances during a render. Before notation parsing/rendering, confirm missing choices once using the visual-presets matrix: recommend 9:16, slate-gray, black-multiply and no character overlay, with the standard lilac/orange hand palette. Also confirm camera, the converge-arc or pulse-only motion, typography/status and the compatible pipeline. Retired themes/surfaces are not offered for new work. Default milestone recommendation is first-four keyframes. Old theme names remain available for historical calls. Reuse actual choices already given in this task; defaults are suggestions, not consent. Keep the confirmation quote/message reference in `aiyoupu-production/v2`. All portable presets disable character overlays. Do not add personal characters or media to the package, defaults, examples or generated preview. This configuration gate is separate from the two content approvals below. Audits and tool diagnostics are not new video production.

New formal audio jobs require [content and performance-time evidence](references/performance-quality.md). New `bind` requires `--production`; `--quality` is required for formal audible jobs. Three energy onsets, a DTW path, successful import, or Agent-generated confidence cannot certify content. Do not relabel candidate anchors as observed. Keep unresolved pitches/arrangements/repeats blocked or explicitly draft. Legacy jobs remain inspectable; rebind before a new formal export.

When PDF/image and XML coexist, inspect/freeze original scope before synchronization: run `source-scope` with an evidence-bound inventory. Different measure counts block full-score correspondence; an excerpt needs explicit source-measure mapping. Different BPM alone is not proof of a different arrangement. `quality-request` can prepare an unapproved listening worksheet directly from candidates, before a reviewed map exists; a candidate worksheet cannot authorize production.

For material guidance, use [recommended input combinations](README.md#准备什么素材). Prefer corrected MusicXML with audio rendered from that same score when generated accompaniment is acceptable, or corrected MusicXML plus the same arrangement/excerpt recording when preserving a performance. MIDI requires explicit assignments; PDF/images require notation preparation/review. MP3 alone needs a score or an available external transcription path; built-in analysis does not transcribe complete polyphony. Explain these as fewer uncertain preparation steps, not measured success-rate percentages. Additional files help only when their versions correspond; retain actual content/time review.

When comparing completion likelihood or choosing among mixed inputs, read [input-specific routes and evidence](references/input-routes.md). Distinguish MP3+PDF/image, MP3+MusicXML, and MP3+MIDI; name missing external stages and never imply they are bundled. Audio candidates require symbolic events first. Report input-specific real completion rates only with a denominator and an independent content/time reference; otherwise use recommendation tiers and not_measured. A rendered preview or protocol-test pass is not a verified song completion.

Use direct wording in user-facing input advice: explain whether the input can be used and what must happen first. Say “最推荐”, “可以做，先识谱并校对”, or “建议先补对应乐谱”, with the applicable material named. Avoid vague labels such as “条件推荐” without a concrete next action. Preserve actual tool-availability and content/time review requirements.

## Read the gate before acting

Run `node <skill>/scripts/aiyoupu.mjs gate --job <frozen-job.json> [--approval <keyframe-approval.json>]` before each review stage and immediately after the user replies. It reports which of the three states you are in and what that state forbids.

- `WAITING_FOR_SCORE_APPROVAL` (gate 1): produce the review, show per-measure comparison, revision differences and remaining doubts, then end the turn. Ask the user in plain words.
- `WAITING_FOR_KEYFRAME_APPROVAL` (gate 2): render real keyframes plus short audition and motion clip, show them with the audio source/profile/mix and camera path, then end the turn.
- `READY_FOR_RENDER` (gate 3): both approvals recorded. Export with the same frozen job and props; never regenerate or edit them between review and render.

The command also returns `showBeforeAsking` (what must be on screen first), `askUser` (what to ask), and `mustNot` (what invalidates the gate). Treat a non-null `stale` field as blocking: the approval belongs to a different job, so re-review instead of reusing it. Never answer a gate from memory; run it.

## Execute the task with two content review stops

1. **Discover/classify.** Reuse the current project and explicitly authorized compatible tools. Missing PATH or a probe timeout is not evidence of absence. Reliable MusicXML/MIDI take priority over re-recognition. PDF/staff images prefer installed professional OMR; missing tools produce options, not invented transcription. Jianpu requires explicit key/octave/rhythm interpretation. Never silently write a per-song recognizer or simplify voices.
2. **Prepare and review notation.** Retain editable MusicXML, real pitch/duration/meter/rest/chord/voice/staff/beam/tie/slur semantics. Check original/reflow crops for every measure; balanced bars are not correctness. `notation-audit` adds revision differences, dense/connected/polyphonic pilot measures and evidence-bound doubts. Use `--previous` after corrections and `--expected-measures` when a user identified a bounded change. Show unexpected changes; do not reset already-correct music for camera edits. New PDF/image `score-request` requires `--notation-audit`. Show crops/differences/doubts, return WAITING_FOR_SCORE_APPROVAL and END THE TURN. Agent self-review cannot approve.
3. **Record real user consent.** Quote actual user words with the displayed requestId/message reference or use their review-page response. Never fabricate actor=user or approval. Score response records provided/synthesize/silent; generated audio choice does not approve unseen timbre. Local JSON binds versions, not human identity.
4. **Produce the approved song/audio.** Preserve the original animation and native SVG geometry. Same-pitch ties sound once for their full duration; slurred pitches remain separate; beams are not ties. Discover with `audio-plan`: user recording first, then existing sampled engine/font. `audio-render` exports the complete approved XML through verified MuseScore Basic; `audio-master` records explicit global gain/padding and protects audible release tails. New checked bind needs `--audio-evidence`. Do not register Agent-generated waveforms as user recordings. Built-in `synthesize --preview-only` is calibration draft only; never replace production audio with custom oscillators just to pass alignment.
5. **Show actual keyframes and audition.** First show four reviewed musical measures (pickup is separate), then cover full-song risk positions before formal export. Use the same final full-song master/props/job for preview/export. `keyframes` generates real frames and a short audition/motion clip. Show audio source/profile/mix plus both hands/chords/line changes/connections/camera. Return WAITING_FOR_KEYFRAME_APPROVAL and END THE TURN. Optional early timbre audition is useful, not a mandatory third gate. A 10–15s excerpt cannot replace the full-song master. Audio/engine/mix changes invalidate this review.
6. **Export after both approvals.** `render --approval ... --confirmed` uses the frozen job. --confirmed alone cannot bypass review. Verify decoded streams, audibility, duration, fps/size and sampled sounding attacks. A missing energy peak is inconclusive for dense/legato music: preserve sound and return needs_review; never shorten decay or change notes to satisfy the detector. Do not fake a passing report. Retain actual commands, inputs and results.

## Recognition quality and limits

Inspect scan quality, page/crop provenance, accidentals/key/clef/octave, dots/beams/tuplets, rests, chord count, voices/hands and tie vs slur. Start difficult long scores with a representative 3–5 measure pilot; cross-check with a second existing method when useful. A model reading twice is not independent ground truth. Never claim an accuracy percentage without a human-corrected benchmark. Keep per-measure uncertainty evidence and explain each correction.

Two failures on one path require diagnosis/alternatives. If no reviewable result exists after roughly ten minutes, report blockers; do not silently run an hour. Complete routine work autonomously inside each stage; do not ask micro-permission for ordinary reversible steps or authorized mixing adjustments.

Use an installed professional OMR adapter when available. Judge notation against the original source; successful engraving or video export does not replace source review. See [usage](README_使用说明.md) and [prompts](examples/agent-prompts.md). Preserve legacy jobs for inspection; re-bind new work with the current V2 configuration, notation, time-map and quality evidence rather than overwriting finished artifacts.
